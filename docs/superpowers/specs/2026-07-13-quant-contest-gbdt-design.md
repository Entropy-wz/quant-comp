## 1. 背景与目标

### 1.1 赛题摘要

基于匿名多标的时序数据，预测每个样本的风险调整表现目标 `target`。评分指标为**加权零均值 R²**（全零预测得分为 0）。私榜采用 Time-Series API 顺序推理；评测环境 CPU 4 核 / 12GB / 无 GPU，模型加载 ≤180s，单 `time_id` 平均推理约 50ms。

### 1.2 数据规模（public_release_20260630）

| 项目 | 数值 |
|------|------|
| 训练行数 | ~13,227,692 |
| 测试行数 | ~3,217,458 |
| 标的数 | 15 |
| 特征数 | 323 (`feature_*`) |
| responder 数 | 47 (`responder_*`) |
| 训练分区 | `train_partition_000` … `_008` |
| 测试分区 | `test_partition_000` … `_002` |

训练含 `weight` / `responder_*` / `target`；测试与私榜推理仅含 `row_id,time_id,asset_id,feature_*`。

### 1.3 团队约束（已确认）

- **目标**: 冲奖认真打
- **算力**: 本机 RTX 4060（专用 8GB + 共享约 32GB）；线上 Jupyter 8 核 / 12GB
- **经验**: 有 ML 与树模型基础，时序/量化比赛经验不多
- **节奏**: 高强度，几乎每天可推进
- **路线**: GBDT 主线；不做 NN 优先；晚期异质 NN 不在本设计范围内

## 2. 整体架构

### 2.1 仓库分工

```text
quant/
  public_release_20260630/     # 官方数据与 runner（只读参照）
  workspace/                   # 自建工作区
    data/                      # 指向官方 data（链接或配置路径）
    notebooks/                 # EDA / 诊断（不进提交包）
    src/
      io/                      # parquet 分区读取
      metrics/                 # weighted zero-mean R²
      validation/              # 时序切分、purged CV、embargo
      features/                # 特征选择与轻量衍生
      models/                  # LGB / XGB / CatBoost 封装
      ensemble/                # 折/种子/模型融合
    experiments/               # 实验配置与指标日志
    artifacts/                 # 模型与预处理参数
    submission/
      public/                  # 公榜 CSV
      strategy/                # 私榜包：main.py + model/
  docs/superpowers/specs/      # 本设计与后续计划
```

本地负责训练与实验；线上环境用于轻量验证与提交；私榜交付物必须可在官方 CPU 环境顺序推理。

### 2.2 主流程

1. EDA：缺失、分布、漂移、`weight`/`target`/`responder` 关系  
2. 锁定时序验证协议（后续调参只信该协议）  
3. LightGBM V0 基线 → 特征与辅助目标 → 多模型/多种子集成  
4. 同一套 `predict` 逻辑生成公榜 CSV 与私榜 `main.py`  
5. 每次提交前用官方 `timeseries_api` runner 做正确性 + 耗时门禁  

### 2.3 硬原则

- 训练可用外部资源；推理必须满足 4 核 / 12GB / ~50ms  
- 禁止未来信息；标准化与填充统计仅在训练窗内估计  
- 显式限制线程数：本地评估 `max_cpu_threads ≤ 4`，线上开发 ≤ 8  
- 公榜用于确认，不当主调参信号  

## 3. 数据、验证与防泄漏

### 3.1 读取策略

- 使用 polars / pyarrow **分区惰性读取**，避免 20GB 级数据一次载入撑爆内存  
- 特征统一 `float32`，索引保持整数类型  
- 全量训练在本机完成；线上 12GB 仅小样实验与推理检查  

### 3.2 验证协议（先锁死）

1. 按 `time_id` 排序后做 walk-forward / 多折时序切分  
   - 建议：最后约 20% `time_id` 作最终 holdout；此前做 3–5 折 expanding 或 rolling  
2. 验证折前设置 **embargo**（空出一小段 `time_id`），降低标签窗口重叠带来的伪相关  
3. 主指标：**weighted zero-mean R²**，公式与官方一致，必须使用 `weight`  
4. 辅指标：按 `asset_id` 分解得分、按时间段稳定性、预测是否塌缩近 0  
5. 公榜每天次数稀缺：仅当本地 CV 有明确提升（或为多样性集成）时提交  

### 3.3 防泄漏清单

- 标准化 / 分位数 / 缺失填充：只在训练折计算，再应用到 valid/test  
- 历史衍生特征：只允许当前及过去 `time_id`，并与 `Model` 内状态机一致可复现  
- `responder_*`：仅训练期可见；不得假设测试/私榜可读取  
- 8/23 标签回补：作为扩展训练数据，用**同一验证协议**重训后再定最终模型  
- 禁止利用未来缺失模式、未来分布或未授权外部行情  

### 3.4 `weight` 与 `responder_*`

**weight**

- 训练：作为树模型 `sample_weight`  
- 验证/选模：加权 R²  
- 可选后处理：在验证折上估计简单校准，优先稳住高权重样本  

**responder_***

- 先做与 `target` 的相关性/可预测性分析  
- 用途限于：辅助回归头、多输出、分阶段训练；若把 responder 预测当特征，必须验证无泄漏且推理路径可复现  
- 推理输入永远不含真实 `responder_*`  

## 4. 建模、特征与集成

### 4.1 模型主线

1. **LightGBM** 为默认主力  
2. **XGBoost / CatBoost** 作为后期异质补充（不在 P0 三线并行）  
3. 统一接口：同一特征矩阵、同一 CV、同一指标；线程数显式限制  

### 4.2 训练目标

- 主任务：回归 `target`；损失在 MSE / Huber 等中按验证加权 R² 选择  
- 辅助：对高相关 responder 做多输出或分阶段训练；以验证决定去留  
- `predict` 输出必须为有限浮点；非法值裁剪/置 0，避免整步作废  

### 4.3 特征版本

| 版本 | 内容 | 约束 |
|------|------|------|
| V0 | 原始 323 特征 + 缺失填充 + `asset_id` 编码 | 最快出分 |
| V1 | 按标的短窗历史（mean/std/diff 等），`Model` 内 `deque` 维护 | 单步必须远低于 50ms |
| V2 | 重要性 + 稳定性筛选，去冗余 | 降维保推理 |

不做：过重全截面大矩阵、超长序列特征、推理期重型预处理。

### 4.4 调参与集成

- 先锁 CV，再调树深/叶子数/`min_data_in_leaf`/采样率/`learning_rate` 等  
- 决策看 **CV 均值与折间方差**；公榜只验证方向  
- 早停基于验证折；最终用最优轮数在更大时间窗重训  

集成顺序：

1. 同模型多种子 / 多折平均  
2. LGB + XGB（可选 CatBoost）验证折加权；权重禁止用测试标签估计  
3. 可选简单尺度校准 `a * pred`，`a` 仅在验证折估计  
4. 集成体同样必须通过 runner 耗时门禁  

### 4.5 私榜模型形态

策略包内包含：

- 预训练 booster 文件  
- 特征列表与填充/编码参数  
- `main.py`：`Model.__init__` 加载；`predict(test)` 轻量特征 + 推理 + 返回与 `test` 等长的一维预测  

单 `time_id` 截面约 15 行；复杂度预算花在特征与模型大小，而非 batch。

## 5. 提交工程与门禁

### 5.1 双轨交付

- **公榜**: `row_id,target` CSV  
- **私榜**: 含 `main.py` 的策略压缩包（≤约 10 次，最新有效）  

公榜与私榜必须共享同一套特征与推理语义，避免“批量脚本能跑、API 不通”。

### 5.2 提交前门禁（全部通过才提交）

1. 本地 `timeseries_api` runner 成功  
2. 行数完整；无 NaN/Inf  
3. `model_init_seconds < 180`；`mean_predict_seconds` 明显低于 0.05s（留余量）  
4. 线程数已限制；内存可在 12GB 内合理估计通过  
5. 相对上一版有本地 CV 提升，或有明确多样性理由  

### 5.3 实验纪律

- 每次实验记录：配置、指标、模型产物标识，写入 `experiments/`  
- 公榜次数留给真正有把握的版本  
- 公榜异常高分先自查泄漏，再决定是否沿用该思路
